### 🎮 GameStore: a complete commerce loop, end to end

Started as a React UI exercise. I kept asking what an actual store needs behind the pretty grid, and it turned into a full-stack app with the whole loop: **discover → wishlist → cart → checkout → own**. Two audiences share one API: customers get live search, a wishlist, checkout, a library, a profile with their rewards ledger and a settings page; admins get a separate portal with full CRUD over games and users.

🔗 [Backend](https://github.com/Robotbino/gameStore-backend) · [Frontend](https://github.com/Robotbino/gameStore) · In-repo handbook: [API side](https://github.com/Robotbino/gameStore-backend/tree/main/docs) · [UI side](https://github.com/Robotbino/gameStore/tree/main/docs)

<details open>
<summary><b>Engineering notes: checkout, auth, schema, tests</b></summary>

- **Checkout that respects money, even fake money.** One transaction snapshots each line's title and price, grants ownership and returns a `DEMO-` receipt. The rewards ledger (earn 10 points per R1, redeem 100 points for R1 off) is always recomputed on the server. Card, Stripe and Payflex are all simulated: card details never leave the browser, and a card number ending in 0002 is declined locally so the failure path can be exercised.
- **Security is the backbone, not a bolt-on.** Stateless JWTs, USER/ADMIN roles in one ordered filter chain, identity taken only from the token (never from a `?userId=`), and authorities reloaded from the database on every request: one extra read per call, in exchange for a role change taking effect immediately. A public `/demo` page walks through the 401 → 403 → 200 access ladder.
- **Built to be trusted.** Flyway owns the schema through six versioned migrations with `ddl-auto=validate`, so drift stops the app at startup instead of hiding. The API is 26 routes across 7 controllers, and 63 integration tests run it against in-memory H2 (MySQL-only constraints are on the known-limitations list). The two repos share one engineering handbook, searchable, with diagrams and a scorecard, and each README keeps a plain list of known limitations.
- **Small things that add up.** Debounced live search with a keyboard-navigable combobox, server-side pagination, optimistic wishlist toggles, skeleton loaders, and a motion system that respects `prefers-reduced-motion`.

</details>

### 👔 Employee Manager: stateless auth across two apps

Plenty of tutorials stop at "login works". I built this one to find out where token-based auth actually leaks: the seam between an API and a client that has to remember everything. Login and the filter chain are done; the employee routes themselves are still open, and closing them is the first item on the MVP roadmap.

<details>
<summary><b>Engineering notes: the JWT seam, theming, decisions</b></summary>

- **Java 17 / Spring Boot 3 REST API** over employee records. Registering and logging in issue JWTs, and a once-per-request filter validates the Bearer token on every call. The employee routes themselves are still open; the architecture doc names closing that gap as the first of four scoped MVP changes, alongside a global error contract, server-side pagination and CSV export.
- **The Angular side holds up its end.** An HTTP interceptor attaches the token and signs out on a 401 or 403; a route guard keeps the protected routes protected, with a return URL, instead of just hiding the nav link.
- **A UI that only promises what it does.** Light and dark themes with measured WCAG AA contrast (lowest 6.16:1 in light, 5.04:1 in dark), a dense table that drops columns by priority on smaller screens, distinct loading, empty, no-results and error states, and toasts instead of `alert()`. Three buttons that led nowhere were removed, not styled.
- **Decisions on paper.** The API ships an architecture and MVP roadmap doc; the client records its theme and layout choices as three ADRs and keeps a `CONTEXT.md` glossary that separates User, Employee and Employee Code.

</details>

🔗 [Repository](https://github.com/Robotbino/CodePairs) · [Live Demo](https://codepairsgame.netlify.app/)

<details>
<summary><b>Engineering notes: derived state, game design, accessibility</b></summary>

- **Game state as derived state.** One service holds the raw state in writable signals, and everything else (multiplier, accuracy, rank) is `computed` from it, which removes a whole class of stale-UI bugs. The board locks during a mismatch, every deal gets fresh card ids, and the confetti runs outside Angular's zone.
- **Actual game design.** Three difficulties, each with its own grid, lives and par time, from a 2×2 board in 12 seconds to 4×3 in 70. Consecutive matches ramp a combo multiplier from 1× to 3×, and every win is graded S, A, B or C.
- **Neo-brutalist "Paper & Ink" design system** built on CSS custom properties, with 3D CSS card flips. Every button splits into a stationary hit box and a moving face, so a press can't slide off its own target.
- **Playable by everyone.** Keyboard controls, screen-reader announcements for every flip and match, full reduced-motion support, and Jasmine/Karma unit tests on the game rules, the scoreboard and the card.

</details>

### 🌌 Personal Portfolio: an Awwwards-inspired site

I didn't want a résumé with a nav bar. Boring. This one is a single continuous scroll: five destinations (Home, Experience, About, Certifications, Contact) that wrap into a seamless loop, floating over a WebGL aurora and a star map drawn from real stars.

🔗 [Repository](https://github.com/Robotbino/PorfolioWebsite) · [Live Demo](https://binohlongwana.netlify.app/) · [ADRs](https://github.com/Robotbino/PorfolioWebsite/tree/main/docs/adr)

<details>
<summary><b>Engineering notes: the loop, the frame pulse, the dependency diet</b></summary>

- **No router.** The whole site is one scroll loop with a cloned first section at the end, so reaching the bottom wraps back to the top without a jump or a route change.
- **One frame loop drives everything.** A GLSL aurora and a WebGL star map, both rendered with OGL, share a single `requestAnimationFrame` pulse outside Angular's zone, which keeps change detection off the 60 fps hot path. The star map sets each star's depth from its real distance (log-scaled), tints the halos by spectral class in dark mode and swings one camera between destinations; if WebGL is slow or software-rendered it falls back to SVG for the session, and phones get a CSS aurora instead.
- **Lean by decision.** The only third-party runtime libraries beyond Angular are OGL and RxJS: no UI kit, no animation library, no icon font. three.js was rejected at roughly 129 kB gzipped, inline SVG icons replaced an icon font, fonts are self-hosted, and every component is OnPush, enforced by lint. The move to Angular 21 took `npm audit` from 3 critical and 33 high findings to zero critical and zero high.
- **Every real decision is an ADR.** Fifteen so far, including one that was proposed and rejected, and each records the alternatives it turned down. The repo also ships an interactive onboarding guide for anyone reading the code cold.
- **Every push to `main` and every pull request is checked.** CI runs lint, a format check, all 29 spec files, and a build that generates the Content-Security-Policy and fails if it can't.

</details>
